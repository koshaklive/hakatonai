# 🧪 Модуль тестирования и оценки качества (Evaluation Suite)

Данная директория содержит эталонные наборы данных (Ground Truth), сценарии валидации диалогов и автономный скрипт прогона тестирования (`run_eval.py`) для интеллектуального помощника по регламентам ДОУ Банка России.

Оценка качества проводится детерминированно: без привлечения сторонних LLM-судей, строго по правилам, цитатам и структурным проверкам.

---

## 📁 Структура файлов директории

| Файл / Каталог | Назначение |
|---|---|
| **`gold.json`** | Основной датасет из 40 эталонных вопросов с точными цитатами, ссылками на пункты и стоп-словами. |
| **`gold.md`** | Человекочитаемая таблица золотого датасета для ручной экспертной проверки. |
| **`module_scenarios.json`** | 8 сквозных диалоговых сценариев заполнения модульных документов (FSM-тесты). |
| **`draft_check_cases.json`** | 5 тестовых черновиков (4 с типовыми нарушениями ДОУ + 1 полностью корректный). |
| **`run_eval.py`** | Автоматизированный раннер тестов: офлайн-валидация и бенчмарк против API. |
| **`reports/`** | Каталог с результатами прогонов и файлом `eval_report.md` со списком расхождений. |

## 🎯 Структура датасета `gold.json` (40 кейсов)

Датасет покрывает ключевые требования кейса[cite: 1]:
1. **Фактологические (12 шт.):** точные сроки, подписанты, зоны ответственности по главам 5–11 Инструкции[cite: 1].
2. **Ловушки регламента (8 шт.):** исчисление сроков «до» vs «не позднее» (п. 6.4)[cite: 1, 29], сроки рассмотрения (10 vs 3 дня, п. 10.3)[cite: 1, 52], порог пояснительной записки (>3 стр., п. 10.12)[cite: 1, 53], порядок 8 шагов визирования (п. 10.6)[cite: 1, 52, 53], срочность (п. 6.7)[cite: 1, 30], отмена актов (п. 8.19.8)[cite: 1, 40], лимит адресатов (п. 8.12.4)[cite: 1, 38].
3. **Матрица обязательного визирования (6 шт.):** проверка комплексных маршрутов (приказы по ИС, рабочие группы ИТ/не-ИТ, внешние письма)[cite: 1, 2].
4. **Модульные документы (4 шт.):** критерии соответствия (п. 9.16.1)[cite: 1, 50], правила удаления служебных отметок, выбор модуля[cite: 1, 3].
5. **Out-of-Domain (4 шт.):** вопросы, отсутствующие в регламентах ДОУ (отпуска, командировки, парковки)[cite: 1]. Ожидается жесткий отказ без галлюцинаций[cite: 1].
6. **Clarification (4 шт.):** неполные запросы, требующие от бота встречного уточнения (вид документа, предмет)[cite: 1].
7. **Ambiguous / Спорные (2 шт.):** проверка обработки расхождений между документами[cite: 1].

## ⚙️ Спецификация контракта схемы `gold.json`

Каждый элемент в `gold.json` имеет строгую структуру[cite: 1]:
```json
{
  "id": "Q01",
  "category": "factual | trap | matrix | module | ood | clarification | ambiguous",
  "question": "Текст вопроса живым языком сотрудника",
  "needs_clarification": false,
  "clarifying_question": null,
  "expected_answer": "Краткий точный эталонный ответ",
  "expected_points": ["10.3"],
  "must_include": ["10 рабочих дней"],
  "must_not_include": ["3 рабочих дня"],
  "source_quote": "Точная цитата из Инструкции (до 15 слов)",
  "difficulty": 2,
  "trap": "Описание логической ловушки регламента"
}
